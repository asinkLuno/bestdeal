# 维护与验证

## 修改入口

- 功能开关：`Runtime/FeatureSettings.cs`，使用原生 `ModConfig`；默认全部开启，`OnChanged` 清除旧报价并使刷新失效。
- 顾客购买条件或预算：`ClientDemand` 与 `QuoteOptimizer.Collect`。
- 推荐组合：`GroupedKnapsack`；候选分组、柜台标记和文案留在 `QuoteOptimizer`。
- 报价与真实成交不一致：先核对 `PriceProbe` 与游戏柜台挂特征调用链，不加经验倍率修补。
- 鉴定与行情：分别修改 `Appraisal`、`MarketWatch`。
- 中英文提示：`Presentation/L10n.cs`；读取 `LocHelper.GetCurrentLocaleCode()`，中文语言使用中文，其余回退英文。
- 面板切换或刷新：`ClientSession`；位置与字体：`Hud`；标题栏拖动：`HudDragHandle`；位置与开关偏好：`HudPreferences`（官方 mod 数据目录的 `hud.json`）。
- 游戏接口变更：先查官方 modding 指南，再用 `tools/DumpCs` 或完整反编译器核对本机程序集。

## 自动检查

```bash
# 算法检查无需游戏程序集，也不安装测试框架
dotnet run --project tests/BestDeal.AlgorithmChecks -c Release
# 实际引用游戏程序集编译，但不部署
dotnet build BestDeal -c Release -p:Deploy=false
# 工具编译
dotnet build tools/DumpCs -c Release
```

算法检查链接生产求解器源码，覆盖预算边界、组内互斥、组合优于贪心和小规模穷举对照。同时覆盖大预算精度、溢出边界和同价稳定性；不验证游戏 API 或副作用恢复。

## 游戏内验收

涉及游戏行为的更改仍需手动检查，构建通过不能替代以下验证：

| 场景 | 观察结果 |
| --- | --- |
| 中英文切换（含暂无顾客、报价、早晨行情、卖家提醒、鉴定） | 文案按游戏语言刷新，长英文换行，金额、数量和涨跌符号不变；其他语言使用英文 mod 提示 |
| 「推荐赃物最高热度」设为 0 / 25 / 100，库存与柜台含热度为阈值及阈值 ±1 的商品 | 只推荐热度 ≤ 阈值的商品；柜台等价替换遵守同一过滤；全部超阈值时显示无合适商品；应用后重算，重启保留设置 |
| 热度设置滑块打开、拖动、恢复默认、关闭后重开 | 标签显示当前滑块整数值；拖动实时更新，恢复默认显示 100；未应用就关闭不保存，重开显示已保存值；中英文提示正常 |
| 模组齿轮中的五个开关，应用、恢复默认、重启游戏 | 默认全开；分别关闭后对应提示消失；报价关闭时独立行情、真伪和估价仍可使用；设置重启后保留，中英文标签正确 |
| 主菜单、读盘、进入店铺 | 无异常刷屏，主菜单无主面板 |
| 开店前有涨跌新闻、无新闻、对应类别无库存 | 行情与库存建议正确，开店后退出行情，闭店后不再弹出；次日早晨恢复 |
| 卖家带来涨价 / 降价类别、多类型物品、多新闻同类叠加或抵消 | 交易内收购分区匹配类别、涨跌幅和物品名，净零不提示 |
| 卖家延迟摆货、买下部分或全部物品、结束交易、下一位顾客 | 半秒内刷新，已购货物和旧顾客提醒消失；买卖兼营时保留报价面板 |
| 普通顾客到柜台，延迟填充需求 | 类别、预算、价格随需求更新 |
| 彩票兑奖顾客到柜台 | 需求显示“中奖彩票”，缺失翻译不显示 translation error |
| 不重复顾客、同款多件、堆叠物品 | 分组数量正确，柜台上的等价同款可标记就位，同款不同数量、价格或赝品警告不会被替代；一件实物不会重复匹配多条推荐 |
| 两个后柜台之间转移物品、拿上或拿下柜台 | 就位标记与推荐正确 |
| 按推荐逐件上柜、同价实例在库存间搬运 | 需求和价格不变时最优总价稳定，柜台等价同款优先显示；不重复顾客不因已有同款在柜而丢弃其他候选 |
| 有限预算耗尽、大预算组合 | 零预算不再推荐正价商品，大预算组合合计不超过预算 |
| 推荐价格与真实上柜台价格 | 普通物品一致；带货容器按已知边界记录差异 |
| 读价前后物品与子物品 | 特征列表恢复，没有移动或顾客反应 |
| Eleanor 到店、库存中有 luxury_supply_crate，自动报价及刷新 | 扫描不触发箱子陷阱；实际放上柜台后剧情仍正常触发 |
| 赝品未识破 / 已识破、切换游戏语言 | 理由本地化和前缀正确 |
| 香烟 / 邮票检查：真品、赝品、假冒真品、真品标成赝品 | 实际状态正确，标称一致不等同于真品；关闭放大镜检查界面后提示消失 |
| 香烟 / 票券有多个 ISSUE 标签 | 逐条显示对应赝品依据，长文本换行，无需选择质疑选项 |
| 仅放置物品、未打开检查界面 | 不显示独立真伪鉴定提示 |
| 无条件特征的物品用放大镜检查 | 明确提示无法判断，不误报真品 |
| 鉴定面板打开、改价、关闭 | 真值、评级随输入更新，关闭后提示消失 |
| 交易结束、下一位顾客、退出店铺重进 | 检查旧报价和会话残留，注意设计文档中的生命周期限制 |

## 游戏升级与发布

1. 用新版游戏程序集构建，核对 Harmony 目标方法及库存字段。
2. 核对柜台挂特征调用链、鉴定评级阈值、新闻变化值和收购牌家族。
3. 运行自动检查和受影响的游戏内验收，记录游戏版本、SDK、命令及未验证项。
4. 发布时同步 `manifest.xml` 的 `ModVersion`、`GameVersions` 和入口加载日志版本。单纯内部整理不必升级版本。
5. 执行部署构建，确认 `Mods/BestDeal/` 仅需 DLL 和 manifest，重启游戏检查 F8 日志与 `mod-scan best_deal`。

依赖保持为游戏自带程序集，`Private=false`。不引入 BepInEx，不复制 Harmony，不自行 `PatchAll`；新增能力需求时同时检查清单与官方加载器约定。

## 2.8.0 本地验证

接入原生模组配置，提供五个默认开启的独立功能开关，设置由游戏保存并跨存档共用。真伪开关控制检查提示及推荐清单的赝品警告；柜台等价匹配仍保留原有真伪约束。关闭报价仍跟踪当前顾客，保证卖家新闻提醒独立工作。配置变化清除旧报价并使报价和早晨行情缓存失效。

使用本机游戏程序集核对 `ModConfig` / `ConfigEntry<bool>` 签名。算法检查及 Release 构建部署结果见本次工作记录；游戏内配置控件、保存恢复、各开关组合及 `mod-scan best_deal` 仍需手动验收，未变更已验证游戏版本。

报价使用 `max_stolen_heat` 整数配置（0–100，默认 100），替代旧的 `recommend_stolen_items` 开关；旧配置键由游戏保留但不再使用，新阈值首次使用取默认 100。候选收集使用游戏 `StolenHelper.IsStolenItem` 与 `GetFoundChance` 读取实际赃物热度，仅排除热度大于阈值的商品，无赃物状态的商品正常参与。过滤在读价和分组求解之前执行，柜台等价替换也只使用过滤后的候选。本机反编译核对了接口：热度读取 `STOLEN_VALUE_INT`，普通初始化热度为 25/50/75/100。算法检查和 Release 构建部署通过；游戏内阈值边界及保存恢复仍需验收。


### HUD 重构验收

- 开店准备 → 接待顾客 → 交易完成：面板切换及时，无旧报价、无等待占位。
- 买卖兼营：售卖推荐与收购行情同框；纯收购不显示无合适商品。
- 无货、预算不足：仍保留需求、预算与筛选条件；无限预算显示无限制。
- 推荐清单先待摆后就位，风险跟随商品；长清单及长检查内容可滚动。
- 打开放大镜/估价：检查优先、交易缩为摘要；关闭后恢复完整交易。
- 离店、回主菜单及停用：HUD 无残留。不同语言与屏幕分辨率下检查换行和滚动。
